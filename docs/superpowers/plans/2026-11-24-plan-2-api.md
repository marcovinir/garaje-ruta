# Plan 2 — API pública, API del panel y tipo de cambio: implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** toda la API REST que necesitan la web pública (Plan 3) y el panel (Plan 4): catálogo con filtros y búsqueda, fichas, similares, sitemap y vistas; CRUD del panel con estados, ventas concurrentes, fotos en Cloudinary, catálogos, configuración e historial; revalidación de Next por etiquetas; y el tipo de cambio diario.

**Architecture:** cada app expone `selectors.py` (lecturas), `services.py` (escrituras y reglas, siempre con su `HistorialCambio`), `serializers.py` (forma de los datos) y vistas delgadas. Las dependencias externas van detrás de interfaces con un doble en memoria para las pruebas (SOLID D, como el `Notificador`): `AlmacenFotos` (Cloudinary), `Revalidador` (Next) y `ProveedorTipoCambio` (open.er-api.com). Los efectos externos se disparan con `transaction.on_commit`.

**Tech Stack:** lo del Plan 1 + `cloudinary` (SDK de Python) y `requests`.

**Spec:** `docs/superpowers/specs/2026-11-23-garaje-ruta-design.md` (§6, §7, §8, §9, §10). Pendientes de la revisión del Plan 1: comentario en la issue #12.

## Global Constraints

- Todo lo del Plan 1 sigue vigente (español, `/api/v1/`, errores `{"detalle","campos"}`, PR por issue, `main` protegida, fusionar con CI en verde).
- **Pruebas:** `docker compose run --rm backend pytest -q`. Ninguna prueba llama a Cloudinary, a Next ni a internet: usan `AlmacenFotosMemoria`, `RevalidadorMemoria` y `ProveedorTipoCambioFijo`, elegidos por settings en `config/settings/pruebas.py`.
- **Permisos:** toda vista bajo `/api/v1/panel/` declara `permission_classes` con `tiene_permiso`/`tiene_alguno` (la tarea 1 lo hace cumplir con una prueba). Las vistas públicas declaran `AllowAny` y `throttle_scope = "publico"` (salvo `vistas`).
- **Visibilidad pública:** un artículo es visible si `estado == "disponible"` y, si es repuesto, `cantidad > 0`. Un `reservado` no sale en listados pero su ficha se abre con la etiqueta «Reservado».
- **Dinero:** colones enteros. `precio_usd = round(precio_colones / tipo_cambio.venta / 10) * 10` (entero); `null` si no hay tipo de cambio.
- **Ruta pública** de un artículo: `/{"autos"|"repuestos"}/{slugify(titulo)}-{id}`.
- **Etiquetas de revalidación:** `"articulos"` (listados, inicio, sitemap), `"articulo-{id}"`, `"catalogos"` y `"configuracion"`.
- Errores de negocio con `apps.comun.errores.Conflicto` (409) y mensajes en español del §7.

## Review Focus

1. **Dos «Vendí 1» simultáneos sobre un repuesto con cantidad 1** → uno vende, el otro recibe 409 «Solo quedan 0»; nunca cantidad negativa ni dos ventas. → tarea 6.
2. **Búsqueda sin tildes o con errores leves** («corola», «camara retroceso», «alternador accent») → encuentra «Toyota Corolla», autos con «Cámara de retroceso» en la descripción y el alternador. → tarea 3.
3. **Ficha de un artículo oculto pedida por su id** → 200 con `estado_publico = "no_disponible"` y **ningún** dato del artículo (ni título). → tarea 4.
4. **Borrar o reemplazar fotos de un artículo sembrado** → nunca borra de Cloudinary un `public_id` de `garaje-ruta/ejemplo/` (lo comparten varios artículos). → tarea 7.
5. **El usuario Demo llamando a cualquier escritura del panel** (incluidas las rutas nuevas de este plan) → 403. → prueba de barrido en la tarea 1, ampliada al final de cada tarea.
