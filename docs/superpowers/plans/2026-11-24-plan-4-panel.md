# Plan 4 — Panel de administración en Next.js: implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** el panel privado de Garaje Ruta (login, listado responsivo con acciones rápidas, formulario de autos y repuestos con fotos subidas directo a Cloudinary, «Vendí 1» con deshacer, compartir, usuarios, configuración y catálogos) en una ruta configurable, cómodo en celular, tablet y escritorio.

**Architecture:** el panel vive en `frontend/src/app/panel/` y es casi todo Client Components: lee y escribe la API del Plan 2 (`/api/v1/panel/…`, `/api/v1/auth/…`) por el rewrite de Next, con la cookie de sesión de Django y el CSRF, usando TanStack Query; los formularios usan React Hook Form + Zod. `src/proxy.ts` (que ya decide el 308/404 de las fichas) reescribe `NEXT_PUBLIC_PANEL_RUTA/*` → `/panel/*`, responde 404 a `/panel/*` directo cuando la ruta configurada es otra y agrega `X-Robots-Tag: noindex`. Las fotos se comprimen en el navegador y suben firmadas directo a Cloudinary; Django solo guarda los `public_id`. La seguridad real son los permisos de la API (HU-06); el panel solo oculta lo que el rol no puede hacer.

**Tech Stack:** Next.js 16.4 (App Router, `cacheComponents`), React 19, TypeScript, Tailwind v4 (tokens de `globals.css`), `@tanstack/react-query` 5, `react-hook-form` 7 + `@hookform/resolvers` + `zod` 4, `@dnd-kit/core` + `@dnd-kit/sortable` (reordenar fotos), Vitest + Testing Library + `msw` 2. Backend: Django 5.2 + DRF (`pytest`).

**Spec:** `docs/superpowers/specs/2026-11-23-garaje-ruta-design.md` (§7 reglas, §8 fotos, §9 roles y `PANEL_RUTA`, §10 API del panel, §11 panel responsivo). **Mockups aprobados:** https://claude.ai/artifact/UU9fVdfzyPRwWmdNseRvuQ, página «Panel» (listado en tarjetas y tabla, formulario de auto con fotos, usuarios, configuración); identidad en la #11. **Base reutilizable:** el panel de Sonrisa Viva (`Proyectos/sonrisa-viva/frontend/src/`): `shared/api/cliente.ts` (CSRF y `ApiError`), `features/panel/auth/` (login, activar, recuperar, `useSesion`), `features/panel/ui/{Avisos,Dialogo,Paginacion}.tsx`, `test/{servidor,render}.ts` (MSW). Se copian a mano y se adaptan (opción B del Plan 1).

## Global Constraints

- Lo de los planes 1–3 sigue vigente (español, una issue = una rama = un PR con `Closes #n`, `main` protegida, fusionar con CI en verde, commits con `Co-Authored-By`).
- **Next 16:** leer `frontend/AGENTS.md` y `frontend/node_modules/next/dist/docs/` antes de usar una API. `middleware` se llama **`proxy`**, su `matcher` debe ser constante, y con Cache Components toda página empieza con 200 (los códigos HTTP reales salen del proxy). Un Client Component que use `useSearchParams` va dentro de `<Suspense>`.
- **Ruta del panel:** una sola variable `NEXT_PUBLIC_PANEL_RUTA` (por defecto `/panel`; empieza con `/`, sin barra final, solo `[a-z0-9-]`). En Django, `PANEL_RUTA` con el mismo valor (enlaces de los correos). Todos los enlaces del panel se arman con `rutaPanel()`; nada escribe `"/panel/"` a mano fuera de `app/panel/`.
- **Responsive (§11):** celular < 768 px = navegación inferior, listado en **tarjetas** con acciones rápidas, formularios a una columna; tablet 768–1023 px = tarjetas en dos columnas y menú lateral plegable; escritorio ≥ 1024 px = menú lateral fijo, **tabla** con orden por columna y acciones en línea, formulario a dos columnas (datos | fotos). Nada se sale a 360 px.
- **Identidad (#11):** los mismos tokens y fuentes de la web (`globals.css`); estados con color **y** texto (`EtiquetaEstado`); campos con contorno `borde-campo`; objetivos táctiles ≥ 44 px; foco visible; `aria-live` para avisos.
- **Nielsen (§11):** confirmación antes de acciones destructivas (eliminar, desactivar usuario), «Deshacer» en el aviso tras vender, errores que dicen cómo seguir, los errores de campo de Django (`{"detalle","campos"}`, también anidados como `auto.anio`) junto a su campo.
- **Permisos (§9):** el panel muestra u oculta acciones según `yo.permisos`; una página sin permiso muestra «No tenés acceso a esta sección». Códigos: `articulos.ver|crear|editar|cambiar_estado|eliminar`, `ventas.registrar`, `catalogos.agregar|gestionar`, `usuarios.gestionar`, `configuracion.editar`.
- **Fotos (§8):** lado mayor 2000 px, WebP (JPEG si el navegador no codifica WebP) a 0,8, orientación EXIF corregida; firma en `POST /api/v1/panel/fotos/firma/`; subida directa a `https://api.cloudinary.com/v1_1/{cloud_name}/image/upload` con barra de progreso, máximo **3 en paralelo**, máximo **15 fotos**; la primera es la principal; guardar con `PUT /api/v1/panel/articulos/{id}/fotos/` (lista ordenada de `{public_id, ancho, alto}`).
- **Pruebas:** `cd frontend && npm test` (Vitest, la red se simula con MSW con datos parecidos a `sembrar`) + `lint`, `format:check`, `build`; backend `docker compose run --rm backend pytest -q`. Cada pantalla se revisa además en el navegador con `docker compose up -d`, `sembrar` y `npm run dev` (usuarios de `sembrar`: admin, colaborador y demo; claves en el README). Los códigos HTTP del proxy se miden con `npm run build && npx next start`, nunca con `next dev`.
- **Fuera de alcance:** historial visible y reportes (etapa 3, #16), Playwright y despliegue (Plan 5, #15), cambiar el logo desde la configuración.

## Review Focus

1. **La sesión vence a mitad de un formulario** (la API responde 401/403 por sesión) → aviso «Tu sesión terminó» y paso al login con `?siguiente=` que vuelve a la misma pantalla; nunca un error mudo ni un guardado que parece exitoso. → tareas 2 y 3.
2. **Dos personas venden el último repuesto a la vez** (la segunda recibe 409 «Solo quedan 0») → aviso con el mensaje de Django y la fila se actualiza con la cantidad real; el «Deshacer» de la primera sigue funcionando. → tarea 5.
3. **Una foto falla a mitad de la subida** (sin red, Cloudinary 4xx, archivo que no es imagen o HEIC que el navegador no decodifica) → las demás siguen y se conservan; la fallida muestra el error con «Reintentar» o «Quitar»; «Guardar» queda deshabilitado mientras haya subidas en curso y avisa si alguna falló. → tarea 7.
4. **El usuario demo (solo lectura)** → no ve crear, editar, vender, cambiar estado, eliminar, usuarios, configuración ni catálogos; si abre `…/articulos/nuevo` a mano ve «No tenés acceso a esta sección». → tareas 3 a 9.
5. **`NEXT_PUBLIC_PANEL_RUTA=/gestion-9x2`** → `/gestion-9x2/articulos` funciona, `/panel/articulos` da **404**, las respuestas del panel llevan `X-Robots-Tag: noindex`, los enlaces internos y el del correo de activación usan `/gestion-9x2`, y el panel no aparece en `robots.txt` ni en `sitemap.xml`. → tareas 1 y 2.
